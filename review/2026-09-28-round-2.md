**What is good. I looked for reasons to say otherwise and did not find them:**
- The architecture reads in under 3 minutes. `VoiceProvider` is still the seam. `server/` is 185
  lines, as the README says, and imports the app's own `gradeTranscript` and zod schemas, so app
  and server cannot drift.
- `data/rubrics/*.yaml` are the best artefact in the repo. Each one has four anchored descriptors,
  a named framework with a full citation (CCL for SBI, Rosenberg 2015, Patterson et al. 3rd ed.)
  and an `evidence` instruction. `data/prompts/grader.yaml` adds weak/medium/strong calibration
  examples, and `prompt.test.ts` holds those examples to the evidence rule.
- The ElevenLabs integration is correct where I could check it. The RN entry really does run
  `registerGlobals()` and `setSetupStrategy()` on import
  (`node_modules/@elevenlabs/react-native/dist/index.react-native.js:1-50`), so importing it lazily
  and then using `@elevenlabs/client`'s `Conversation` is legitimate. Token minting uses the
  documented `/v1/convai/conversation/token`. The Claude call uses a current model id
  (`claude-opus-5`), `output_config.effort`, structured output via `betaZodOutputFormat`, a cached
  system prompt and the `fallbacks: 'default'` refusal fallback. I checked all of it against the
  Claude API reference.
- No secrets reach the client: `grep -rnE "sk-ant|xi-api-key|ELEVENLABS_API_KEY|ANTHROPIC_API_KEY" app src`
  → none. There are no TODOs and no "not wired yet" throws.
- D-010 is fixed for real. I built the web app with `EXPO_PUBLIC_MOCK=0` and tapped Start. It now

  is needed…` when denied) with *Try again* / *Back to conversations* buttons. In round 1 it

**What costs points (new this round unless marked):**
- **Stop doesn't stop a connecting session (D-022).** `end()` sets `endReason` and calls
  `this.conversation?.endSession()` while `conversation` is still `null`
  (`src/voice/elevenlabs.ts:107-111`). `startSession` then connects anyway (`:51-56`). Every later
  stop returns early at `if (this.endReason) return`. I wrote a throwaway probe using the repo's own
  vitest mocks: `session connected after stop? true; endSession calls: 0`, and after a second stop
  still `0`. On screen, "End conversation" is live during "Connecting…" (`app/session/[id].tsx:153-159`)
  and does nothing, the call then comes up, and the button stays dead. Leaving the screen runs the
  same no-op cleanup (`src/session/useConversation.ts:46-50`), which leaves an invisible session
  with the mic open.
- **The documented retry-on-bad-schema is unreachable (D-025).** The SDK strips `maximum`/`minLength`
  from the schema it sends, then re-validates in `.parse()` and **throws** (`@anthropic-ai/sdk/helpers/beta/zod.js`).
  Probe: `schema sent to API has "maximum": false`; `score 5 -> THROWS AnthropicError`;
  `empty quote -> THROWS AnthropicError`; `truncated -> THROWS SyntaxError`. So
  `grade.ts:29-33`'s `safeParse` never sees bad output from the real grader. That output becomes
  `app.onError` → 502 "The service is unavailable". The test that "re-requests once when the output
  does not match the schema" passes only because it uses a fake `callModel`.
- **The evidence gate is a substring check, not "word for word" (D-026).** `isGrounded` is
  `normalise(turn).includes(needle)` with a two-alphanumeric minimum (`src/grading/evidence.ts:23-27`).
  Probe: `"no" -> true` against "I know…", `"ch" -> true`. A 16/16 grade whose four quotes are
  `it`, `an`, `ch`, `no` gives `findUngrounded → []`. README.md:40 says "appears word for word".
- **Prompts are inlined in TS, against the repo's own rule (D-031).** The retry feedback prompt
  (`src/grading/grade.ts:32, :36-45`), the transcript wrapper (`server/src/grader.ts:26`) and the
  scenario/calibration framing (`src/grading/prompt.ts:28-33, :73`) are string literals.
  CLAUDE.md:139 says "never inlined as string literals in TypeScript".
- **`/server` is an open proxy (D-030).** It has no auth, no rate limit and no cap on turn length
  (`server/src/app.ts:15-18`). It binds `*:8797` (`ss -ltnp`), and each `/grade` can cost two
  Opus 5 calls at `max_tokens: 16000`. On hackathon Wi-Fi, anyone on the LAN can spend the
  owner's credit.
- **Still dead or unread:** `grade.boundary_held`, `grade.safety_flag` and `Attempt.endReason` are
  written but never read. `GradeResult.modelCalls` and the server's `downgraded` field are read
  only by tests. `userText()` is used only by a test, and that test joins turns with `\n`, so the
  mock-quote check is weaker than the runtime gate. `assets/splash-icon.png` is unreferenced, and
  `assets/icon.png` is byte-identical to phase 0 (md5 `cb975bba…`). All of this is D-017,
  partially fixed.
- **Untested critical path, again:** the retry delta comes from `findPreviousAttempt`
  (`src/attempts/store.ts:46-49`), which is unchanged, still filters by scenario only and still has
  no test (D-019). Nothing tests `useConversation`, `server/src/grader.ts` or `server/src/voice.ts`
  against their real SDKs.
- **CLAUDE.md still lies (D-011, partial).** §5 names 7 paths that are not committed
  (ACCESSIBILITY.md, SAFETY.md, EVALS.md, src/purchases/revenuecat.ts, src/a11y/, evals/gold,

## Pass D: the product critic

- **Does the persona push back?** On paper, yes, finally. `data/prompts/persona.yaml` gives Sam a
  goal, a hidden objection ("embarrassed that they don't yet know how to fix" two security
  comments), a tone, and per-level acceptance rules ("Agree only when the level above says you
  would"). That is a persona, not a script. In the only thing a judge can run, though, the
  personas still fold on cue ("Fine. First part by 4pm…"), and L3 replays the L1 transcript
  (Playwright: `identical_L1_vs_L3_transcript: True`).
- **The difficulty card is a cheat sheet.** The brief prints each level's acceptance rule verbatim:
  "only agrees after a second, specific ask", "Accepts only a concrete, time-boxed plan after two
  pushbacks" (`app/scenario/[id].tsx:43-55`). The user is told the password before the
  conversation starts. Show the *feel* ("defensive, protective of the work") and keep the rule in
  the prompt.
- **Would a first-time user freeze at L1?** In live mode, quite possibly. Sam opens with "Hey,
  what's up? I've only got a few minutes before standup." and the user has a mic, a "Your goal"
  line, no opener hint, no visible turn counter against the 6-turn cap, and no way to type instead
  (D-028). The first "Try saying" arrives only after the first failure.
- **Do the scores feel earned?** The rubric makes them *earnable*, which is a big step up from
  round 1. "Most first attempts score 2… Do not round up to be encouraging" is the right
  calibration instruction. What the judge actually sees undercuts it: +8/16 in one retry, a mock
  1/4 that the rubric on screen says is a 2 (D-027), and a gate that would accept "no" as evidence
  (D-026).
- **Safety.** It is now written down but not shipped correctly. The persona is told to hang up on
  "stop"/distress. The provider reports any agent hang-up as `stop_condition`, and the screen grades
  it. So a distressed user gets "Scoring your conversation…" and a scorecard (D-023, probe:
  `{"status":"ended","reason":"stop_condition"}`). A bare "stop" also collides with the scenarios'
  natural language: "can we stop adding scope?", and the grader's own calibration scenario is
  "Ask a colleague to stop interrupting you". The mic permission text promises audio is "never
  stored". ElevenLabs keeps call audio for two years by default, and DEVICE.md never says to turn
  that off (D-024).
- **Is the paywall resented?** There is still no paywall to resent. The D-020 risk stands: PLAN.md
  keeps the wall on the 4th graded session, which after scenario 1 + one retry + scenario 2 is
  "Retry", the hero action.
- **Is it boring?** For a judge, yes, still. Tap, watch 15 s of text crawl, read a card, and repeat
  for 19.5 s. The product that would not be boring (a defensive voice arguing back, then a card
  quoting you) exists only as untested code.
